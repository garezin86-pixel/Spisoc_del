# AI-инструменты CRM и бот

Пакет `src/ai` — общий слой «фраза → действие в CRM». К нему подключены Telegram-бот (текст и голос) и веб-панель
ассистента (`/api/ai/*`); любой другой клиент подключается так же: создать `AIContext`, вызвать `AIAgent`, показать `Turn`.

## Как это устроено

```
фраза / голос ─► LLM (Groq) выбирает инструмент ─► реестр ─► сервис CRM ─► БД
                                                    │
                                   права, поиск клиента/сотрудника, подтверждение
```

| Модуль | Что делает |
|---|---|
| `src/ai/registry.py` | `Tool`, `ToolRegistry`: описание для LLM, роль-гейт `allowed`, `run`, `commit` |
| `src/ai/tools/crm.py` | `find_client`, `open_client`, `list_clients`, `list_clients_without_contact`, `pipeline_summary`, `create_client`, `create_deal`, `move_deal_stage`, `list_deals`, `add_note` |
| `src/ai/tools/tasks.py` | `create_task` (можно с клиентом) и прежние команды: `get_tasks` (в т.ч. «задачи клиента …»), `update_task_status`, `update_task_priority`, `update_task_description`, `assign_task` |
| `src/ai/agent.py` | `AIAgent`: очередь вызовов, подтверждение, выбор из нескольких |
| `src/ai/resolve.py` | поиск клиента/сотрудника/стадии: регистр, ё/е, ООО/ТОВ, падежи («Петру» → «Петр») |
| `src/ai/llm.py` | единственное место, знающее про Groq |
| `src/ai/runtime.py` | общий агент процесса (`get_agent()`): реестр + Groq |
| `src/ai/pending_store.py` | ожидающее решение («да/нет», выбор) на сервере: Redis, 10 минут, по одному на пользователя |
| `src/routers/ai_router.py` | веб-API ассистента: `/api/ai/message`, `/api/ai/confirm`, `/api/ai/choose` |
| `frontend/src/components/AIPanel.jsx` | веб-панель ассистента (кнопка ✨ справа внизу) |
| `src/bot/handlers/ai_assistant.py` | Telegram-адаптер: кнопки «Да/Нет», выбор, текстовые ответы «да/нет» |
| `src/routers/ai_router.py` | Веб/API-адаптер: `POST /api/ai/message`, `/confirm`, `/choose` |
| `src/ai/pending_store.py` | Ожидающее решение пользователя на сервере (Redis, 10 минут, по одному на пользователя) |
| `src/ai/runtime.py` | Общий для бота и веба агент (реестр + Groq) |
| `frontend/src/components/AIPanel.jsx` | Панель ассистента в вебе (кнопка ✨ справа внизу) |

В `src/ai` нет импортов `aiogram` и `src.bot` (проверяет `tests/test_ai_agent.py`).

## Правила

- **Чтение** (`find_client`, `list_*`, `get_tasks`) выполняется сразу.
- **Запись** — только после «да»: `run` возвращает `Confirm` с уже разрешёнными id, `commit` выполняется после
  подтверждения. Выполняется ровно то, что пользователь видел в вопросе.
- **Несколько подходящих записей** — `Choose`: бот показывает кнопки, инструмент запускается заново с выбранным id.
- **Несколько вызовов в одной фразе** идут по очереди: следующий готовится после решения по предыдущему. Отказ или
  сбой записи останавливает остальные вызовы. Не больше 5 вызовов за фразу.
- **Права — в коде, не в промпте:**
  1. `Tool.allowed(user)` — роль-гейт: недоступный инструмент не показывается LLM и не выполняется, даже если LLM его
     «придумала» (например, `create_client` у обычного сотрудника);
  2. предпроверки в `run` (ответственный за клиента/сделку) — отказ до вопроса «да/нет»;
  3. сервисы CRM проверяют права ещё раз при выполнении; `commit` повторно проверяет роль.
  `tests/test_ai_permissions.py` сверяет решения инструментов с поведением HTTP API по каждой роли.
- **Лимиты:** текст и голос используют один счётчик `check_voice_rate_limit` (`VOICE_RATE_LIMIT_COUNT` команд за
  `VOICE_RATE_LIMIT_WINDOW_SECONDS`), проверка — до вызова LLM. Текст длиннее 1000 символов не отправляется в LLM.

## Веб и API

Три эндпоинта ведут тот же диалог, что и бот:

1. `POST /api/ai/message` `{text, context?: {client_id}}` → `{messages, pending, changed}`. Чтение возвращается сразу;
   запись и выбор из нескольких вариантов возвращают `pending` `{id, kind: confirm|choose, text, options}`. Новая
   команда отменяет неотвеченный `pending`.
2. `POST /api/ai/confirm` `{pending_id, confirm}` — «да/нет». `changed: true` — действие выполнено, интерфейсу пора
   обновить данные.
3. `POST /api/ai/choose` `{pending_id, option_id}` — выбор варианта; дальше обычно приходит `confirm`-вопрос.

Ошибки: `404` — клиент из контекста не найден (чужой компании тоже), `409` — действие уже выполнено или устарело
(двойной клик «Да» выполнит запись один раз), `422` — такого варианта нет, `429` — лимит команд (общий с ботом, заголовок
`Retry-After`), `502` — сбой LLM. Права, лимитер и история диалога те же, что у бота.

**Контекст экрана.** Если открыта карточка клиента, её `client_id` передаётся в `context`: модель получает подсказку
«пользователь смотрит клиента X», а инструменты, которым не назвали клиента, берут его (например «запиши заметку: …»).

## Как добавить инструмент

```python
async def _run(ctx: AIContext, args: dict) -> Outcome:
    client = await resolve_client(ctx, "my_tool", args)      # ClientModel | Choose | Refuse
    if is_outcome(client):
        return client
    if not can_edit_client(client, ctx.user):                # предпроверка прав
        return Refuse("⛔ ...")
    return Confirm(text="Сделать X для «...»?", tool="my_tool", args={"client_id": client.id})   # запись
    # чтение: return Done("результат")

async def _commit(ctx: AIContext, args: dict) -> str:
    await ctx.deals.some_service_method(...)                 # только через сервисы CRM
    return "✅ Готово"

registry.register(Tool(name="my_tool", description="...", parameters={...}, run=_run, commit=_commit,
                       allowed=is_manager, hint="«фраза» — my_tool."))
```

Тексты результатов — обычный текст (без HTML): транспорт экранирует и оформляет их сам.

## Что в боте

- Любое текстовое сообщение в личном чате, которое не забрали меню, мастера (FSM) и команды, уходит в агента
  (роутер `ai_assistant` подключён последним).
- Ответ на вопрос о подтверждении: кнопки или текст «да» / «нет». Любой другой текст отменяет ожидающее действие и
  обрабатывается как новая команда.
- Нажимать кнопки может только тот, кто задал команду.

## Модель LLM

Модели Groq задаются в `.env`: `GROQ_LLM_MODEL` (по умолчанию `openai/gpt-oss-120b`) и `GROQ_STT_MODEL`
(`whisper-large-v3`). Groq регулярно отключает модели: `llama-3.3-70b-versatile` закрыта 16.08.2026 — запросы к ней
возвращают 404 `model_not_found`. Актуальные замены: https://console.groq.com/docs/deprecations. Для семейства GPT-OSS
код добавляет `reasoning_effort=low`, `include_reasoning=false` и увеличенный лимит токенов; для других моделей эти
параметры не передаются (если нужна особая настройка, правьте `_model_options` в `voice_ai.py`).
GPT-OSS не поддерживает параллельные вызовы инструментов: составная фраза может вернуть только первое действие.

## Веб-API ассистента

| Запрос | Что делает |
|---|---|
| `POST /api/ai/message` `{text, context?: {client_id}}` | команда; чтение отвечает сразу, запись и выбор возвращают `pending` |
| `POST /api/ai/confirm` `{pending_id, confirm}` | «да» выполняет подтверждённое действие, «нет» отменяет |
| `POST /api/ai/choose` `{pending_id, option_id}` | выбор из предложенных вариантов (клиент, сотрудник, сделка, стадия) |

Ответ: `{messages: [...], pending: {id, kind: confirm|choose, text, options}|null, changed}`; `changed=true` — действие
выполнено и интерфейсу пора обновить данные. Правила те же, что у бота: права в инструментах, запись только после «да»,
общий с Telegram лимит команд (429 с `Retry-After`) и общая память диалога. `pending_id` одноразовый: повтор «да» (двойной клик),
чужой или устаревший id дают 409 и ничего не выполняют. Новая команда отменяет неотвеченный вопрос.

**Контекст экрана.** Если открыта карточка клиента, панель шлёт `context.client_id`: модель получает подсказку «пользователь
смотрит клиента X», а инструменты берут этого клиента, когда он не назван («создай задачу позвонить завтра в 10»). Чужой или
несуществующий клиент в контексте — 404, до обращения к LLM и без списания лимита.

Ожидающее действие хранится в Redis (`ai:pending:{компания}:{пользователь}`, 10 минут). Без Redis — в памяти процесса: при
нескольких воркерах подтверждение может попасть не туда, пользователь увидит «устарело» и повторит команду.

## Открытая карточка и «рабочий клиент»

- `open_client` показывает сводку по клиенту (контакты, ответственный, сделки, открытые задачи, последний контакт); в вебе ответ
  содержит ещё и команду интерфейсу `actions: [{"type": "open_client", "client_id": N}]` — панель открывает карточку.
  В Telegram команда игнорируется, достаточно текста сводки.
- Клиент, которого только что нашли или назвали (`find_client` с одним результатом, `open_client`, любой инструмент, разобравший
  имя клиента), запоминается как «рабочий» на 30 минут (`src/ai/focus_store.py`, Redis, без него — память процесса). Следующие
  команды без названия («создай ему задачу позвонить завтра») получают подсказку модели «речь шла о клиенте X». Это только
  подсказка: перед записью пользователь видит в вопросе «да/нет», к какому клиенту относится действие.
- Открытая на экране карточка (веб) важнее: она подставляется жёстко — `create_task` без названия клиента привяжет задачу к нему.
- Модели запрещено писать «открываю», «создал» и т.п. без вызова инструмента (правила в `src/ai/llm.py`).

## Ограничения

- `create_task(client)` ставит настоящую связь `client_id` у задачи (поле есть в API: `POST/PATCH /tasks`,
  фильтр `GET /tasks/filter?client_id=`); у задач, созданных до миграции `n9c0d1e2f3a4`, связи нет.
- Голосовой ввод в вебе пока нет: в панели только текст (голос работает в Telegram).
- Без Redis ожидающее решение хранится в памяти процесса: при нескольких воркерах «да» может прийти не на тот процесс
  (будет ответ «устарело»).
- Качество выбора инструментов зависит от LLM; в тестах она подменена сценариями.
