# Установка Spisok Del на сервер клиента

Инструкция для установки на Linux-сервер с Docker. Цель — чтобы человек, не знающий проект, поднял систему и загрузил
свою базу клиентов примерно за 15–20 минут (из них 5–10 — первая сборка образов, это зависит от сервера и интернета).

## Что понадобится

- Сервер с Linux: от 2 ядер, 2–4 ГБ памяти, 20 ГБ диска.
- Docker и Docker Compose v2 (`docker compose version` должен отвечать). Установка: <https://docs.docker.com/engine/install/>.
- Доступ к коду проекта (`git clone` или архив).
- Для HTTPS (необязательно): домен, A-запись которого указывает на сервер, и открытые порты 80 и 443.
- Для Telegram-бота (необязательно): токен от @BotFather.

## 1. Получить код

```bash
git clone <ссылка на репозиторий> spisok-del
cd spisok-del
```

## 2. Настроить `.env.prod`

```bash
cp .env.prod.example .env.prod
```

Откройте `.env.prod` и замените все значения `REPLACE_ME_…`. Секреты удобно получать так (каждый раз новое значение):

```bash
openssl rand -hex 32      # для SECRET_KEY, REFRESH_SECRET_KEY, ADMIN_SECRET_KEY — три РАЗНЫХ значения
openssl rand -hex 16      # для паролей
```

### Обязательные значения

| Переменная | Что это |
|---|---|
| `SECRET_KEY`, `REFRESH_SECRET_KEY`, `ADMIN_SECRET_KEY` | Секреты подписи входа и админ-панели, три разных. Без них приложение откажется стартовать. |
| `POSTGRES_PASSWORD` | Пароль базы данных. Только буквы и цифры: он подставляется в адрес подключения, символы `@ : / #` его ломают. |
| `GRAFANA_ADMIN_PASSWORD` | Compose требует его всегда, даже если мониторинг вы не включаете. Подойдёт любое значение. |
| `FRONTEND_URL` | Адрес, по которому откроют систему (`https://crm.your-domain.example` или `http://IP:8000`). |

`POSTGRES_USER` и `POSTGRES_DB` можно оставить как в примере.

### Если нужен Telegram

Задайте `BOT_TOKEN` (и `SUPER_ADMIN_TG_ID`). **Без токена контейнер `bot` не стартует** и будет бесконечно перезапускаться:
если Telegram не нужен, запускайте систему без него (см. следующий шаг).

### Необязательное

`GROQ_API_KEY` (голосовые команды), `R2_*` (вложения в облаке), `VAPID_*` (браузерные уведомления; ключи создаются один раз
командой `python scripts/generate_vapid_keys.py`), `SENTRY_DSN`, `ADMIN_ALLOWED_IPS` (с каких IP разрешена админ-панель
`/admin`; на публичном сервере лучше задать), `APP_NAME` (название в документации API).

`.env.prod` содержит секреты: не добавляйте его в git и никому не отправляйте.

## 3. Запустить

Чтобы не набирать длинную команду, задайте её один раз в терминале:

```bash
export DC="docker compose --env-file .env.prod -f docker-compose.yml -f docker-compose.prod.yml"
$DC up -d --build
```

Без Telegram-бота:

```bash
$DC up -d --build app postgres redis backup
```

(В Windows PowerShell переменную `$DC` не подставить: пишите команду целиком.)

Первая сборка долгая (она собирает и интерфейс, и приложение). Проверьте:

```bash
$DC ps                      # app, postgres, redis, backup — Up; backup станет healthy после первого дампа
$DC logs app --tail 30      # должна быть строка «Application startup complete»
```

Миграции базы применяются автоматически при старте приложения.

## 4. Создать компанию и администратора

```bash
$DC run --rm app python -m scripts.init_instance
```

Скрипт спросит название компании, имя и пароль администратора (Enter — сгенерировать; сгенерированный пароль
показывается один раз, при первом входе система попросит заменить его) и стадии воронки продаж. «Успех» и «Отказ» он
добавит сам. В конце выведет **логин для входа** — он может отличаться от введённого имени.

Хотите сразу посмотреть систему на примере — добавьте `--demo` (загрузит демо-клиентов; они удаляются кнопкой «Удалить демо»
над списком клиентов). Повторный запуск безопасен: если пользователи уже есть, скрипт ничего не изменит. Подробнее — `docs/first-run.md`.

## 5. Открыть и войти

Откройте `http://<IP сервера>:8000` (или `https://<домен>`, если включили HTTPS) и войдите логином и паролем из шага 4.
Сотрудников приглашайте из админ-панели ссылкой-приглашением.

## 6. Загрузить базу клиентов

Вкладка «Клиенты» → «Импорт»:

1. Выберите файл `.csv` или `.xlsx` (первая строка — заголовки; до 5000 строк, 5 МБ). Кодировку и разделитель определяет система.
2. Проверьте сопоставление колонок: названия вроде «ФИО», «Телефон», «E-mail» подставляются сами. Обязательна только колонка с названием.
3. Если в файле нет колонки «Тип», выберите «Компания», «Частное лицо» или «Определять по названию» (догадка по «ООО…»,
   кавычкам и формату «Иванов Иван» — проверьте её в предпросмотре).
4. Нажмите «Предпросмотр»: он ничего не создаёт, но показывает, сколько будет создано, какие строки с ошибками и какие дубликаты
   (тот же телефон, email или название). Затем «Импортировать».

Клиентов можно выгрузить обратно кнопкой «Экспорт» (файл открывается в Excel).

## 7. HTTPS (необязательно)

Для HTTPS есть готовый профиль с Caddy: он сам получает и продлевает сертификат Let's Encrypt. В `.env.prod` задайте:

```
DOMAIN=crm.your-domain.example
APP_BIND=127.0.0.1
FORWARDED_ALLOW_IPS=*
FRONTEND_URL=https://crm.your-domain.example
```

`APP_BIND=127.0.0.1` закрывает порт 8000 от внешней сети: приложение доступно только через Caddy. Именно при этом условии
безопасно `FORWARDED_ALLOW_IPS=*`; без `APP_BIND` его включать нельзя. Затем:

```bash
$DC --profile https up -d
$DC logs caddy --tail 30
```

Сертификат выпускается при первом обращении к домену (обычно за минуту). Если не выпустился: проверьте A-запись домена, что
порты 80 и 443 открыты в файрволе, и сообщения в `$DC logs caddy`. Том `caddy_data` с сертификатами не удаляйте.
Если вы остановили систему командой `down`, поднимайте её снова тоже с `--profile https`.

## 8. Бэкапы и восстановление

Бэкап включён по умолчанию: раз в сутки база сохраняется в папку `backups/`. Эти файлы лежат на том же сервере, что и
база, поэтому периодически копируйте их на другой компьютер или в облако. Как восстановить (и как проверить восстановление
до того, как оно понадобится) — в `docs/backup-and-restore.md`.

## 9. Обновление

```bash
$DC run --rm backup once    # дамп перед обновлением
git pull
$DC up -d --build           # новые миграции применятся сами
```

Если обновление пошло не так, откатите код (`git checkout` на прежнюю версию), а базу при необходимости восстановите из дампа,
снятого на первом шаге.

## 10. Свой бренд (white-label)

Название и логотип на экране входа и в шапке вшиваются в интерфейс при сборке:

```bash
cp frontend/.env.example frontend/.env     # отредактируйте VITE_APP_LOGO, VITE_APP_NAME, VITE_APP_DESCRIPTION
$DC build app && $DC up -d
```

`APP_NAME` в `.env.prod` меняет только название в документации API.

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| `required variable … is missing` при запуске | Не заполнен `.env.prod` или в команде нет `--env-file .env.prod` (используйте `$DC`). |
| `app` сразу завершается | `$DC logs app`: «не заданы обязательные секреты» — заполните три секретных ключа. |
| `bot` постоянно перезапускается | Не задан `BOT_TOKEN`. Укажите токен или запускайте без бота (шаг 3). |
| Порт 5432 занят | В `.env.prod` задайте `POSTGRES_HOST_PORT=55432` (внутри Docker ничего не меняется). |
| Сайт не открывается снаружи | Файрвол сервера: порт 8000 (без HTTPS) или 80 и 443 (с HTTPS). |
| `502`/нет страницы через HTTPS | `$DC ps`: запущен ли `app`; `$DC logs caddy`. |
| Забыли применить миграции после обновления | Они применяются при старте `app`; смотрите `$DC logs app`. |
