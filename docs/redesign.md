# Редизайн интерфейса (ветка `redesign`)

Фронтенд переделан по макету: новая оболочка (боковое меню и верхняя панель), тёмная и светлая темы, переработаны все основные экраны. Бизнес-логика и API остались прежними, кроме изменений из раздела «Бэкенд и база данных» — для них нужна миграция.

## Что изменилось в интерфейсе

### Навигация
Роли разделены: **верхняя панель** переключает группы разделов, **боковое меню** показывает страницы активной группы.

| Группа | Страницы |
|---|---|
| Работа | Главная, Задачи (режимы «Список» и «Канбан»), Проекты, Календарь, Лента, Статистика, Шаблоны |
| CRM | Клиенты, Воронка |
| Коммуникации | Группы, Команда |
| Инструменты | API-токены, Вебхуки, iCal-календарь |
| Всегда внизу меню | Корзина, Настройки |

- Верхняя панель: поиск (`Ctrl K`), группы с выпадающим списком страниц, переключатель темы, чат со счётчиком непрочитанного, уведомления, меню пользователя (профиль, админка, выход). Плавающий пузырь чата убран.
- На экранах уже 900 px боковое меню заменяется выезжающим: группы раскрываются списками.
- Пункта «Канбан» в меню больше нет: это режим вкладки «Задачи». Выбранный режим запоминается (`localStorage`, ключ `spisoc_tasks_view`), а старый `tab = "kanban"` (командная палитра, закладки) открывает «Задачи» сразу в режиме доски.

### Темы и оформление
- Тёмная и светлая темы, переключатель в верхней панели. Цвета — CSS-переменные в `frontend/src/styles.css` (`:root` и `[data-theme="light"]`).
- Вторичный текст осветлён (в тёмной теме контраст с фоном был около 3.7:1).
- Шрифт — Inter. Видимый фокус с клавиатуры у нового меню и кнопок; при включённой системной настройке «уменьшить движение» анимации отключаются.

### Экраны
- **Главная** — дашборд: четыре карточки (задачи на сегодня, просрочено, сделки в работе с суммами по валютам, клиенты без контакта), две колонки: задачи, клиенты без контакта; встречи и воронка по стадиям.
- **Задачи** — список строками (чекбокс, название с метками, срок, статус, исполнитель). Клик по названию раскрывает полную карточку: описание, комментарии, вложения, чек-лист, зависимости, теги, история. Форма «Новая задача» открывается по кнопке. Рядом переключатель «Список / Канбан».
- **Клиенты** — вкладки по статусу со счётчиками, фильтр по типу, таблица (клиент, контакты, статус, ответственный, последняя активность); карточка клиента с хлебными крошками и двумя панелями на «Обзоре».
- **Воронка сделок** — колонки на всю ширину, выбор воронки выпадающим списком, для admin кнопка «+ Воронка» (можно скопировать стадии из текущей). Вкладки B2B/B2C убраны.
- **Проекты** — карточки с прогрессом, участниками и клиентом; фильтр по клиенту; внутри проекта задачи в той же таблице, что и на вкладке «Задачи».
- **Календарь, Лента (с группировкой по дням), Статистика, Шаблоны, Группы, Команда, Корзина** — единый заголовок страницы и карточки.
- **Настройки** — отдельная страница: двухфакторная аутентификация, смена пароля, push-уведомления (карточка переехала со «Статистики»). API-токены, вебхуки и iCal — самостоятельные страницы группы «Инструменты», а не вкладки внутри «Настроек».
- **История изменений** (карточка задачи и «Лента») показывает русские названия статусов и приоритетов, даты в местном формате и **имена** исполнителя, группы, проекта и клиента вместо `#5`.

## Бэкенд и база данных

**Нужна миграция:** `alembic upgrade head` (ревизия `p1e2f3a4b5c6`, добавляет `clients.status` и индекс `ix_clients_status`; у существующих клиентов статус `active`). Откат — `alembic downgrade -1` (значения статусов при этом теряются).

| Область | Изменение |
|---|---|
| Клиенты | Поле `status`: `active` / `inactive` / `blacklisted` (создание, `PATCH`, ответы). Фильтр `GET /api/clients?status=`. Новый `GET /api/clients/status-counts` — счётчики для вкладок (учитывают поиск, тип, «мои», «пора связаться», но не сам статус). |
| Клиенты, список | В каждой строке `last_interaction_at` и `last_interaction_type` — последнее взаимодействие (один запрос на страницу). |
| Клиенты, экспорт | CSV: колонка «Статус» и параметр `status`. |
| Правила | Клиент из чёрного списка не получает напоминание «пора связаться». В блоке «Клиенты без контакта» на главной считаются только активные. |
| Проекты | В ответах `client_name`; `GET /api/projects?client_id=`. Название удалённого клиента не показывается. |
| Профиль | `GET /api/users/me` отдаёт `is_platform_admin` (доступ в SQLAdmin; не то же самое, что `role = admin` — админ своей компании). Ссылка «Админка» в меню пользователя показывается только админам платформы. В списках сотрудников признак не возвращается. |
| История задачи | `GET /api/tasks/{id}/audit` — в каждой записи `names` (`{"user_id": {"5": "admin1"}, ...}`). Лента активности (`/api/analytics/activity`) подставляет имена группы, проекта и клиента. |

Новые и обновлённые тесты: `tests/test_client_status.py`, `tests/test_project_client.py`; в `tests/test_interactions.py` изменено ожидание — в списке клиентов теперь есть `last_interaction_at`.

## Исправления, найденные по пути
- Смена статуса во вкладке «Задачи» была с большой задержкой: после каждого изменения список перезагружался с экраном «Загрузка…». Теперь перезагрузка по WebSocket тихая и склеивает события, а неподтверждённый статус не откатывается запоздавшим ответом.
- Импорт задач из CSV/Excel падал: в `App.jsx` использовалась необъявленная переменная `projectId`.
- После перемещения карточки на доске список показывал старый статус — теперь он обновляется при возврате в режим «Список».
- У модальных окон (итоги импорта, шаблоны) был прозрачный фон: использовались необъявленные переменные `--bg-card`, `--bg-card2` и др. Они определены через новые токены.
- Удалено около 470 строк неиспользуемых стилей старой шапки и прежних макетов (`styles.css`).

## Как обновиться
```bash
git switch redesign
alembic upgrade head          # применить миграцию p1e2f3a4b5c6
cd frontend && npm install && npm run build   # зависимости не добавлялись
```
Backend перезапустить как обычно. Тесты: `pytest tests/test_client_status.py tests/test_project_client.py`.

## Известные ограничения
- Перетаскивание карточек на досках работает мышью. На сенсорных экранах статус задачи меняется кнопкой на карточке, стадия сделки — в окне сделки.
- Список проектов, как и раньше, загружается до 50 штук (фильтр по клиенту работает по загруженным).
- Окна создания сделки, событий и шаблонов получили только новые цвета и шрифт, раскладка у них прежняя.
- Мобильная версия проверялась в режиме эмуляции мобильного экрана браузера; на реальных устройствах стоит пройтись по всем экранам.
- Статус клиента не ограничивает работу (задачи, сделки и встречи с клиентом из чёрного списка создавать можно) — он влияет только на напоминания и блок «без контакта».
