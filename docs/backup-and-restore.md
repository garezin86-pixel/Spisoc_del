# Бэкап и восстановление базы

## Как работает бэкап

Сервис `backup` поднимается вместе со всеми остальными (`docker compose up -d`) и раз в сутки (в `BACKUP_HOUR` по UTC,
по умолчанию 03:00) снимает дамп Postgres в папку `./backups`: `db-ГГГГ-ММ-ДД_ЧЧ-ММ-СС.sql.gz`. Первый дамп снимается сразу
при запуске. Дампы старше `BACKUP_LOCAL_RETENTION_DAYS` (по умолчанию 7) удаляются, три последних остаются всегда.

```bash
docker compose ps                         # backup должен быть healthy (хотя бы один дамп за последние ~26 часов)
docker compose logs backup                # что и когда делал бэкап
docker compose run --rm backup once       # снять дамп прямо сейчас
```

В боевой установке добавляйте к командам `--env-file .env.prod -f docker-compose.yml -f docker-compose.prod.yml`
(как в README), например `docker compose --env-file .env.prod -f docker-compose.yml -f docker-compose.prod.yml run --rm backup once`.

**Важно.** Если выгрузка в R2 не настроена, эти файлы — единственная копия, и лежат они на том же сервере, что и база.
Периодически копируйте `./backups` на другой компьютер или в облако. Дамп содержит все данные и хеши паролей — храните его
как секрет и не публикуйте.

## Восстановление

Восстановление **целиком заменяет** текущую базу содержимым дампа: всё, что появилось после снятия дампа, будет потеряно.
Перед заменой текущая база сохраняется в `backups/pre-restore-….sql.gz` (ротация эту копию не удаляет).

```bash
docker compose run --rm backup restore                                   # список доступных дампов
docker compose stop app bot                                               # остановить приложение
docker compose run --rm backup restore db-2026-10-26_08-13-24.sql.gz --yes
docker compose up -d                                                      # запустить; недостающие миграции применятся сами
```

В конце команда показывает, что оказалось в базе (число пользователей, компаний, клиентов, сделок, задач и версию миграций):
сверьте это с ожидаемым. Без `--yes` команда ничего не меняет, а только объясняет, что произойдёт. Параметр `--no-safety`
пропускает страховочную копию текущей базы — нужен, только если текущая база заведомо не нужна.

Дамп восстановится ровно в то состояние, в котором он был снят: из дампа, снятого, когда в базе был один пользователь,
вы получите одного пользователя.

## Проверьте восстановление до того, как оно понадобится

Бэкап, который ни разу не восстанавливали, нельзя считать бэкапом. Один раз пройдите весь круг на тестовой установке:

1. Загрузите демо-данные или импортируйте клиентов, чтобы в базе было что терять.
2. `docker compose run --rm backup once`, запомните имя файла.
3. Удалите данные (например, «Удалить демо»).
4. Восстановите по инструкции выше и убедитесь, что данные вернулись.
