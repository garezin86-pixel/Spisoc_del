# Smart Tables

Таблицы в стиле Excel как **живое окно в базу CRM**: данные не копируются, правка (этап 4) идёт через
существующие сервисы, поэтому права, проверки и аудит те же, что в карточках.

## Статус этапов

| Этап | Что | Статус |
|---|---|---|
| 1 | Чтение: реестр колонок, `GET /api/tables/...` (клиенты, сделки) | ✅ |
| 2 | Оборудование сделки (`deal_items`: сделка, название, цена) | — |
| 3 | Свои поля (`custom_fields`, `custom_field_values`) | — |
| 4 | Правка ячеек с токеном `_version` и ответом 409 | — |
| 5 | Живая синхронизация (`rows_changed` по WebSocket) | — |
| 6 | Вкладка «Таблицы», грид | — |
| 7 | Сохранённые виды | — |
| 8 | Группировка, итоги по валютам, экспорт | — |
| 9 | Вставка диапазонов | — |

## API (этап 1, только чтение)

- `GET /api/tables` — источники (`clients`, `deals`).
- `GET /api/tables/{source}/meta` — колонки: тип, операции фильтра, списки значений, флаги `editable`, `manager_only`, `linked`.
- `GET /api/tables/{source}/rows` — строки. Параметры: `columns` (через запятую), `filters` (JSON), `sort` (JSON), `page`, `size` (до 200).

Пример: выигранные сделки по менеджерам, крупные сверху:

```
GET /api/tables/deals/rows
  ?columns=owner_name,client_name,title,amount,currency
  &filters=[{"field":"stage_kind","op":"eq","value":"won"}]
  &sort=[{"field":"amount","direction":"desc"}]
```

В каждой строке есть служебные `_id` и `_version` (updated_at записи — токен для правки на этапе 4).
Деньги отдаются строкой, чтобы не терять точность.

## Правила

- Колонки, фильтры и сортировка берутся **только из реестра** `src/services/table_registry.py`. Неизвестное поле, операция не для типа или значение не того типа — 422.
- Запросы идут через ORM-атрибуты (работает `tenant_scope`), `workspace_id` дополнительно ставится явно. Удалённые записи и сделки удалённых клиентов не показываются.
- Читают все пользователи компании, как обычные списки. Запросы — GET, поэтому read-only токены (PAT) тоже работают.
- Новая колонка = одна строка `ColumnDef` в реестре. Новый источник (например, задачи) = колонки + функция соединений.
- Запись через таблицы (этап 4) не должна использовать массовый `UPDATE`: слушатели аудита и инвалидации дашборда его не видят. Только ORM-объекты через сервисы.
